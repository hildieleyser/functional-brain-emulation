Issues Identified
01
Single Subject Dominance
All 8 largest session recordings appear to be from the same participant. The 42 XDF files list 9 subject IDs, but the richest multi-modal data comes from undifferentiated session_* timestamped files. Between-subject variability cannot be assessed with current data.
Subject distribution:
session_* (unnamed) — 14 files, 3.1 GB, 8 modalities each
sub-P001 — 6 files, 13.8 GB (includes 5 _old versions)
sub-P002 — 2 files, 3.7 GB (includes 1 _old version)
sub-P007, P009, 090, 0903, 09031, 0999, 2003 — 1-3 files each, smaller
CRITICAL
Generalizability
02
No Session Contains All Modalities
The lab stack and mobile stack have never been recorded simultaneously. No single XDF file contains all 11 modalities. This means cross-stack correlations (e.g., EEG vs. fNIRS, or DSI-24 vs. Kernel Flow) cannot be computed from any existing recording.
Lab sessions contain: Gazepoint + KernelFlow (x3) + StretchSense + Microphone
Mobile sessions contain: DSI24 + TobiiGlasses (x2) + StretchSense
Missing overlap: EEG never co-recorded with fNIRS
Missing overlap: EMG (Delsys) not present in any exported session
CRITICAL
Cross-modal analysis
03
Kernel Flow Sample Rate Mismatch
All three KernelFlow LSL streams (Red, IR, Quality) report a nominal rate of 5 Hz in their stream metadata, but pyxdf measured effective rates of 8–13 Hz across sessions. This 2–3x discrepancy means LSL timestamp correction may be miscalculating, causing synchronization drift with other streams.
Reported rate: 5.0000 Hz
Measured rates across sessions:
  KernelFlow_Red — 8.08 – 13.14 Hz
  KernelFlow_IR  — 8.32 – 13.13 Hz
  KernelFlow_Quality — 0.99 – 13.62 Hz
Quality stream in one session dropped to ~1 Hz
CRITICAL
Synchronization
04
Short Usable Overlap Windows
Many sessions have limited time windows where all streams are simultaneously active. Streams start and stop at different times, reducing the usable overlapping segment. One session had only 37 seconds of multi-stream overlap.
session_20260306_171345.xdf: 37s overlap (file is 22.5 MB)
session_20260227_145319.xdf: <5s usable (file is 241 KB)
Best sessions (Mar 5-6): 120s+ overlap available
Effective yield: ~877s total across 8 sessions (vs. potential minutes of raw data)

08
Inconsistent BIDS Naming
Subject and session identifiers use mixed conventions. Some use zero-padded numeric IDs (sub-P001, ses-S001), others use bare numbers (sub-090, ses-1), and many have no subject ID at all (session_YYYYMMDD_HHMMSS). This complicates automated analysis pipelines.
Conventions observed:
sub-P001_ses-S001_task-Default_run-001_eeg.xdf — structured
sub-090_ses-010_task-Baseline_run-001_.xdf — different pattern
sub-2003_ses-1_task-Baseline_run-001_.xdf — no zero-padding
session_20260306_091530.xdf — no subject ID

Recommendations
01
Run a combined lab + mobile session. Connect DSI-24, Kernel Flow, Gazepoint, StretchSense, and Delsys simultaneously into a single LabRecorder instance. This is the highest-priority gap — without it, cross-modal EEG-fNIRS analysis is impossible.
02
Fix Kernel Flow stream metadata. Update the nominal_srate in kernel_flow_lsl.py to match the actual output rate (~10-13 Hz), or configure Kortex to output at a stable declared rate. This will fix LSL timestamp correction.
03
Record at least 3 more subjects with the full multi-modal stack to establish between-subject baselines. Target 5+ minute continuous recordings per session for meaningful spectral and correlation analysis.
04
Standardize BIDS naming. Use consistent zero-padded subject/session IDs across all recordings. Move session_* files into the sub-XXX folder structure. Archive or delete _old files after verification.
05
Add pre-recording checklist to start_all.bat that verifies all streams are active and at expected rates before LabRecorder begins. This will prevent aborted/empty recordings and catch rate anomalies early.
